## Load a role into an agent assignment

1. Start from the requested result and the next decision. Pick a role ID from the table or find the entry in Media work routing.
2. Open that role file and its **Agent assignment** section. Provide the current brief or question, evidence and version, named owner and receiver, due time, available tools, and permitted actions. State important unknowns as unknown.
3. Proceed on independently supported work. Route a missing required input or held use to the named owner. Return the artifact, evidence, and check that makes it usable for the intended receiver.
4. Record what was run, what the recipient could use, and what could change the next practice. If the version changes, reconcile affected copies and approvals.

Use this header in a task or Slack thread as needed. The graph files define working capabilities. The project grants actual access and decision authority.

```yaml
assignment:
  role_id: MKT-S
  request: Compare the educator resource entry and destination before drafting a promotion
  outcome: Identify the exact audience promise and the service-owner decision needed
  input_versions: [current brief, educator entry URL, resource URL]
  permitted_actions: [read public pages, analyse, draft internally]
  decision_owner: Programme owner to confirm
  receiver: Named campaign coordinator
  due: Set by the project
  acceptance: Citation and version for each observation, scoped hold, independent next work
```

## Research status

- **Mapped.** Twelve roles based on public employer descriptions. The institutional layer uses Calgary Public Library public service pages, leadership, the 2027–2030 Strategic Plan, and selected 2023–2025 Board minutes and packets.
- **Proposed practice.** Capability, execution and learning graphs. Use them to prepare and check an assignment. Confirm actual project permissions, reporting and release authority before relying on them.
- **Exercised.** Two fresh workers used the routing and role files to define a Stop Motion promotion decision brief and return a proposed school livestream go/no-go handoff from supplied scenarios. Their feedback clarified who leads overlapping campaign and production intake, and separated a rehearsal recording's in-event use from later replay. These were desk exercises. No output was delivered to a Calgary Public Library colleague and no platform operation was exercised.
- **Open evidence.** The source research did not verify the 2026 Board minutes text, current internal tools and permissions, or project-specific assignments and approvals. Tool examples in role graphs are conditional. Asana is read-only.
